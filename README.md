# ברייקדאון – אסטרל HR

מערכת ברייקדאון להפקות: גוגל-שיט כמקור אמת + אפליקציית מעקב מהסט.

## מה יש כאן

| נתיב | מה זה |
|---|---|
| `build.py` | מייצר את הברייקדאון של אסטרל: xlsx עם 5 גליונות + `appsdata.json` |
| `apps-script/` | פרויקט Apps Script (clasp) – רישום ברייקדאונים, מנתח גליונות גנרי, Web App |
| `apps-script/Parse.js` | המנתח הגנרי: מזהה גליון ושורת כותרת, מילוי כלפי מטה, שורות מקטע |
| `apps-script/api.py` | קליינט CLI לבדיקות מול ה-Web App |
| `index.html` | אפליקציית המעקב – קובץ אחד, React UMD, בלי build |
| `out/` | הפלטים: xlsx עם 5 גליונות, `shots.json`, `appsdata.json` |

## ריבוי ברייקדאונים

האפליקציה נפתחת במסך בחירה. כל ברייקדאון הוא גוגל-שיט נפרד, והסטטוסים שלו
נשמרים בגליון מוסתר `_status` **בתוך אותו קובץ** – אז ברייקדאונים לא מתערבבים.

**להוסיף חדש:** ＋ במסך הבחירה, מדביקים קישור לגוגל-שיט. המנתח מזהה לבד
את הגליון ואת שורת הכותרת, ועובד גם על הפורמט הישן: תאים ממוזגים אנכית
נגררים כלפי מטה, מיזוגים אופקיים מזוהים כשורות מקטע (ארוחות/מעברים),
ושורת כותרת שחוזרת בתוך הנתונים מדולגת.

עמודות שמזוהות (עם וריאציות): `#` `יום` `שעה` `מלון` `תלות קאסט` `אשכול`
`לוקיישן` `קטגוריה` `סרטון` `סוג סרטון` `תסריט` `קאסט` `לוגיסטיקה - לקוח`
`לוגיסטיקה - הפקה` `הלבשה` `הערות` `בוצע`. הדרישה המינימלית: `תסריט` + עוד שתיים.

## API

| קריאה | מה מחזיר |
|---|---|
| `GET ?action=list` | רשימת הברייקדאונים |
| `GET ?p=<id>` | `{project, items, statuses}` |
| `GET ?action=diag&p=<id>` | מה המנתח רואה בקובץ (כותרת, מיזוגים, מיפוי עמודות) |
| `POST {action:'add', url, name}` | מוסיף ברייקדאון מקישור |
| `POST {action:'remove', p}` | מסיר מהרשימה (הקובץ לא נמחק) |
| `POST {p, statuses}` | שומר סטטוסים |

## איך זה עובד

```
build.py  →  appsdata.json  →  Data.js  →  [clasp push]  →  Apps Script
                                                                 │
                                                        setup()  ▼
                                                          גוגל-שיט (5 גליונות)
                                                                 │
                                                    doGet/doPost ▼
                                                          index.html
```

- הגליון `ברייקדאון` הוא **מקור האמת** לשוטים. עריכות של הצוות בשיט מגיעות לאפליקציה בפול הבא (כל 15 שניות).
- הסטטוסים נשמרים בגליון מוסתר `_status`, ומשוקפים לעמודת `בוצע` בגליון הברייקדאון.
- דחיית שעות מהאפליקציה נשמרת כ-`tsOverride` ב-`_status` – היא **לא** דורסת את עמודת השעה בשיט.

## גליונות

1. `לוז` – בלוקים לפי יום ושעה, כולל ארוחות ומקרא תלות-קאסט
2. `ברייקדאון` – 70 שורות שוטים
3. `בקשות ללקוח` – מה צריך מהלקוח, משובץ ליום ושעה
4. `פרופס ומשימות` – מי משיג / מי עושה
5. `הנחות ושאלות` – מה סגור ומה עוד פתוח

## עמודת "תלות קאסט"

הדבר שקובע מה אפשר לצלם מתי:

| ערך | משמעות |
|---|---|
| `שחקנים` | חייב את השחקן – שני/שלישי בלבד |
| `שחקנים + עובדים` | שחקן יחד עם עובד/ניצב |
| `עובדים` | עובדים ומנהלים של המלון – גמיש |
| `נציג הנהלה` | עדי פלד / ליז אלפסי – רביעי בבוקר |
| `ביוטי / ללא קאסט` | אינסרטים וידיים בלבד – הגמיש ביותר |

## פקודות

```bash
# עדכון נתונים אחרי שינוי ב-build.py
python build.py                      # מייצר out/appsdata.json
cd apps-script && clasp push --force
# ואז להריץ rebuild() בעורך האפסקריפט (מרנדר מחדש; הסטטוסים נשמרים)

# פריסה מחדש של ה-Web App (אותה כתובת)
clasp update-deployment <deploymentId> --description "vN"
clasp list-deployments
```

## אבטחה – לשים לב

ה-Web App פרוס כ-`ANYONE_ANONYMOUS`, כלומר **כל מי שיש לו את ה-SYNC_URL יכול לקרוא ולעדכן את הברייקדאון**.
זו אותה תצורה כמו בפרויקט מאי. אם `index.html` נדחף לריפו ציבורי – הכתובת חשופה.
חלופה: להעביר את ה-Web App ל-`access: "MYSELF"` או `"DOMAIN"` ולהגיש את האפליקציה מאחורי התחברות.
